# سول — الدولة الملكية الفدرالية الرقمية

> ## ⚖️ القاعدة الحاكمة (RULE-000) — تُقرأ قبل أي سطر آخر
> **كل من عمل في هذا المستودع يجب أن يوثّق كل ما قام به، وأن يترك ما تبقّى موثّقًا بوضوح لمن يأتي بعده.**
> إنشاء ملف ليس إنجازًا؛ الإنجاز هو: تشغيل + اختبار + توثيق + اعتماد + مراقبة.
> التفاصيل الكاملة والقواعد المشتقّة في [`GOVERNING_RULE.md`](GOVERNING_RULE.md). مخالفتها تُلغي العمل.

> ## 🔒 الطريق الإلزاميّ للعمل — لا يُلمس ملفٌ قبل قراءته
> **لا عملَ في مسارٍ محكومٍ بلا بندِ عملٍ حيٍّ باسم جهةٍ واحدةٍ يحجز نطاقَه.**
> مَن يعمل الآن في ماذا؟ الجوابُ في [`docs/work/WORK_QUEUE.json`](docs/work/WORK_QUEUE.json) وحده (`npm run work:list`).
> الطريقُ والقواعدُ وما يُفعل عند التزاحم: [`docs/work/WORK_CONTROL.md`](docs/work/WORK_CONTROL.md)
> — وبوابةُ `npm run check:work` ترفض العملَ المدوّر والتداخلَ قبل الدمج لا بعده.

## ما هذا المستودع

التنفيذ المرجعي لدولة رقمية ملكية فدرالية: الملك هو صاحب السيادة الوحيد، وكل ما دونه وكلاء رقميون
يعملون تحت مرور بوابة التاج، بسجل تدقيق غير قابل للمحو، وصلاحيات محدودة، وإيقاف فوري.

المستودع مبني على ثلاث وثائق تأسيسية موجودة في [`docs/specs/`](docs/specs/) وهي **مصدر الحقيقة**:

| الوثيقة | الدور |
|---|---|
| [`digital-absolute-federal-monarchy-spec.md`](docs/specs/digital-absolute-federal-monarchy-spec.md) | المواصفة التأسيسية — 52 قسمًا: السيادة، المؤسسات، الحقوق، الأمن |
| [`digital-monarchy-comprehensive-spec.md`](docs/specs/digital-monarchy-comprehensive-spec.md) | المواصفة الشاملة — أبواب تفصيلية للحكم والوكلاء والبنية والاقتصاد |
| [`digital-state-build-guide.md`](docs/specs/digital-state-build-guide.md) | دليل البناء — شجرة الملفات، التبعيات، المراحل، الاختبارات |

الوثائق ليست للقراءة فقط: هي **توجيهات تنفيذية**. خريطة تحويلها إلى وحدات ومالكين في
[`docs/DIRECTIVES.md`](docs/DIRECTIVES.md).

## ابدأ من هنا (لكل من يأتي بعدنا)

1. اقرأ [`GOVERNING_RULE.md`](GOVERNING_RULE.md) — القاعدة الحاكمة.
2. اقرأ [`PROGRESS.md`](PROGRESS.md) — ما تم فعلًا وما تبقّى، محدَّث بعد كل عمل.
3. اقرأ [`ROADMAP.md`](ROADMAP.md) — 40 مرحلة من 0% إلى 100% بنِسَب وشروط قبول.
4. اقرأ [`OWNERSHIP.md`](OWNERSHIP.md) — من يعمل على ماذا، ومن يعتمد ماذا.
5. اقرأ [`ARCHITECTURE.md`](ARCHITECTURE.md) و[`docs/DIRECTIVES.md`](docs/DIRECTIVES.md).
6. اقرأ [`docs/work/WORK_CONTROL.md`](docs/work/WORK_CONTROL.md) — **الطريق الإلزاميّ الواحد**، و[`docs/work/ROADMAP_EXECUTION.md`](docs/work/ROADMAP_EXECUTION.md) — ماذا يُعمل وبأيّ ترتيب.
7. شاهِد الحجزَ القائم: `npm run work:list`. ولا تلمس مسارًا محجوزًا لغيرك (`WORK_CONTROL.md` §6).
8. احجز قبل أن تعمل: `npm run work:new -- --title … --owner … --reviewer … --area … --scope …`، ثم املأ عقدَ بندك في `docs/work/orders/`.
9. نفّذ، اختبر، **وثّق قبل الدفع**، ثم أغلق بندك بنقل سطره إلى [`docs/work/WORK_LOG.md`](docs/work/WORK_LOG.md) في التزامة الدمج نفسِها.

## ترتيب الاعتماد المعماري (لا يُعكس)

```
الملك والهوية → جذر الثقة → بوابة التاج → السجل والمراقبة والإيقاف
   → النماذج → مصنع الوكلاء → الحكومة → الأقاليم → الاقتصاد والخدمات
   → الاتصال الخارجي → التوسع → التدقيق المستقل → إعلان 100%
```

## التشغيل والاختبار

```bash
npm install        # بلا تبعيات تشغيل خارجية — أدوات البناء فقط
npm run build      # تحقق الأنواع وبناء TypeScript
npm test           # تشغيل كل اختبارات القبول
npm run verify     # بناء + اختبار + التحقق من سلامة سجل التدقيق
```
