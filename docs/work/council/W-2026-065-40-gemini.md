## 4. المراجعة التحققية والعدائية

### أ. مراجعة علاج عيب الجولة 39 (`TAX_LEVY_MUTABLE_REFERENCE_ESCAPE`)
في الجولة 39 كشف مسبار العضو `gpt` أن دوال الاستعلام في `RevenueService` (`get` و`outstanding`) ونتائج العمليات (`assess` و`collect` و`waive`) تعيد كائنات `Levy` الداخلية كمرجع حي، مما سمح للمستدعي بتعديل حقول الرسم داخليًا (مثل تحويل `status` إلى `'collected'` والتلاعب بمبلغ `levied` و`ratePerMille`) دون قيد في الدفتر أو أمر ملكي أو توثيق في سجل التدقيق.

في الالتزام المجمد للجولة 40 (`3ac5709`)، تم فحص الشفرة في `src/economy/tax.ts` وتبيّن تطبيق العلاج عبر الأبواب الخمسة:
1. `assess`: يُرجع `{ ok: true, levy: { ...levy }, auditId: entry.hash }`
2. `collect`: يُرجع `{ ok: true, levy: { ...collected }, auditId: entry.hash }`
3. `waive`: يُرجع `{ ok: true, levy: { ...waived }, auditId: entry.hash }`
4. `get(levyId)`: يُرجع `levy ? { ...levy } : null`
5. `outstanding()`: يُرجع `[...this.levies.values()].filter((l) => l.status === 'assessed').map((l) => ({ ...l }))`

وحيث إن بنية `Levy` (المعرفة في `src/economy/tax_types.ts`) مسطحة بالكامل ولا تحتوي سوى على حقول بدائية (`string` و`number` و`null`)، فإن النسخ السطحي `{ ...levy }` يماثل تمامًا النسخ العميق، ويضمن عزل الكائن الداخلي عن أي تلاعب خارجي.
