## العيب المانع المقاس

### `RATE_AMENDMENT_REFUSAL_AUDIT_PRIMITIVE_OVERRIDE`

**الموضع.** في `src/economy/tax.ts`:

```ts
const refuse = (reason, extra = {}) => this.deps.audit.append(
  this.actorId, 'rate_amendment_refused',
  {
    base: auditPrimitive(base),
    requestedRatePerMille: auditPrimitive(newRatePerMille),
    reason,
    ...extra,
  },
);

if (!isValidRatePerMille(newRatePerMille)) {
  return refuse('...', { requestedRatePerMille: newRatePerMille });
}
```

المعقّم موضوع قبل `...extra`، لكن فرع النسبة غير السليمة يمرّر المفتاح نفسه داخل `extra`. لذلك ينتصر الانتشار الأخير، ويخزّن `newRatePerMille` الخام، إن كان كائناً قابلاً للتغيير، في قيد `rate_amendment_refused`. ذلك يفلت من العلاج الذي يدّعي أن كل قيد رفض يقنّع المدخل غير البدائي، وهو داخل `src/economy/tax.ts` و`src/economy/tax_types.ts`، أي داخل نطاق البند.

**المسبار القابل لإعادة التشغيل.** أنشأت داخل جذري الملف:

```text

```

المسبار يستورد `dist/` المبني من التجميد، ويبني دولة، ويموّلها، ثم يطلب `amendRate` بأمر ملكي صحيح لكن بـ`newRatePerMille` كائن `{ marker: 'before' }` بدلاً من رقم. بعد أن يعيد الرفض، يتحقق من هوية القيمة المخزنة في آخر `rate_amendment_refused`، ثم يغير `marker` إلى `after` ويتحقق من سلامة السلسلة. خرج تشغيله الحرفي:

`sameReferenceBefore:true` يثبت أن قيد التدقيق يحمل الكائن ذاته لا رمز `auditPrimitive`. و`storedMarkerAfterMutation:"after"` يثبت وصول طفرة المستدعي اللاحقة إلى القيد. و`integrity:false` يثبت كسر سلسلة التدقيق بلا قيد جديد. بقيت النسبة الحاكمة `25` لأن التعديل رُفض، لكن الرفض نفسه سمّم دليل التدقيق؛ فلا يعد رفضاً مغلقاً آمناً.
