## 4. التحقق العدائي وفحص ادعاءات المعالجة الحادية عشرة (Remedy 11)

انتهت الجولة السابعة بإجماع الرفض (gpt REJECTED · grok REJECTED · gemini REJECTED) بعشرة عيوب مسماة تدور حول جذر أساسي هو: `OPAQUE_ABSENCE_STILL_CLOSED_FORM_LIST`، حيث كان حكم غياب الشفرة المعتمة ونفي المنتج قائمًا على قائمة مغلقة من الأشكال النصية والمطابقات السطحية.

ادعت المعالجة الحادية عشرة (في الالتزام `d34d738` والتقرير `docs/test-reports/phase-39-W-2026-040-remedy-11.md`):
1. معالجة الشفرة المعتمة في `scripts/rehydrate_opaque_code.ts` بالأنواع والرموز المحلولة: كشف مستدعى نوعه `Function`/`FunctionConstructor`، وتوقيع محلول لـ `Reflect.get`/`Object.getOwnPropertyDescriptor`/`eval`/`require`.
2. ربط هوية الحاجز برمز محلول في `scripts/rehydrate_barrier_binding.ts` بمطابقة عقدة التعريف وشاهد الرمي البنيوي وحراسة نقطة الاختناق في `StateJournal.read` و`rehydrateFromJournal`.
3. إعلان حد جديد: ستة مواقع حية لاستدعاءات على قيم `any` بلا وسيط يومية (`startsWith`/`trim`/`act`/`verify` في أربعة ملفات خارج النطاق) لا يقيسها الحاجز الساكن ويحرسها الحارس التشغيلي.

وبإعمال عين العداوة والبحث المنهجي عن الثغرات، تم اكتشاف العيوب البنيوية التالية وتأكيدها بالمسابر العملية القاطعة:

### العيب الأول: `RC14_EVAL_CALL_AND_APPLY_BYPASS` (تجاوز الشفرة المعتمة عبر `eval.call` و`eval.apply`)

#### وصف العيب
ادعت المعالجة الحادية عشرة أن «eval يُقاس بالتوقيع المحلول — والاستعارة تُرى بالحل لا بالاسم» (البند §4(1) من التعليمات).
ولكن عند تفحص كود `scripts/rehydrate_opaque_code.ts` (الأسطر 133–147):
```typescript
const decl = libSignatureDecl(n, checker);
if (decl !== undefined) {
  const sym = (decl as unknown as { symbol?: ts.Symbol }).symbol;
  ...
  if (sym?.name === "eval") {
    return "«eval» مُحلَّلُ التوقيعِ — نصٌّ يصيرُ شفرةً في نطاقِهِ ولا يراها النفي";
  }
}
```
تبيّن أن الحاجز يفترض أن استدعاء `eval` يتم دائمًا بالنداء المباشر `eval(...)`.
أما إذا تم الاستدعاء عبر توابع `Function.prototype` المعيارية مثل:
```typescript
eval.call(null, "(globalThis as any).j.record('archive_snapshot', {})");
```
أو:
```typescript
eval.apply(null, ["(globalThis as any).j.record('archive_snapshot', {})"]);
```
فإن:
1. التوقيع المحلول للاستدعاء `decl` يحل إلى `CallableFunction.call` أو `Function.apply` في ملف التعريف المعياري `lib.es5.d.ts`.
2. اسم الرمز المحلول `sym?.name` هو `"call"` أو `"apply"`، وليس `"eval"`.
3. التعبير المستقبل `eval` لا يتم فحصه إطلاقًا داخل الشرط (فحص التوقيع يقتصر على رمز الدالة المناداة مباشرة).
4. نوع القيمة المعادة من `.call` و`.apply` هو `any`.
5. الاستدعاءات على قيم من نوع `any` التي لا تمرر اليومية وسيطًا صريحًا تم استثناؤها عمدًا في الحاجز الساكن (الأسطر 36–41).
6. وسائط `eval.call` هي نصوص حرفية (`string`) وليست كائنات يومية، فلا ينطبق عليها فحص `couldBeJournal`.

#### الدليل العملي والمسبار المقيس
تم تنفيذ مسبارين مستقلين (`PROBE-01-EVAL-CALL` و`PROBE-02-EVAL-APPLY`) عبر حقن الكود أعلاه في `src/data/persistence.ts` وتشغيل الحاجز الساكن `check_rehydrate_census`:
- **خرج المسبار 1 (`eval.call`):** رمز الخروج `0` (اجتاز الحاجز الساكن بالكامل وطبع `✓ حصرُ الإرجاع: 23 صنفًا في النطاق كلُّها مُدَّعاة`).
- **خرج المسبار 2 (`eval.apply`):** رمز الخروج `0` (اجتاز الحاجز الساكن بالكامل وطبع `✓ حصرُ الإرجاع: 23 صنفًا في النطاق كلُّها مُدَّعاة`).

**الأثر:** يستطيع أي كود تنفيذي داخل `src/**` توليد قيود للصنف المعفى `archive_snapshot` وتدوينها في اليومية عبر نصوص ديناميكية مستدعاة بـ `eval.call`، ويبقى الحاجز الساكن أخضر بالكامل، مدعيًا برهان نفي المنتج زورًا!

### العيب الثاني: `RC14_FUNCTION_BIND_DYNAMIC_INSTANTIATION_BYPASS` (تجاوز منشئ الدالة عبر `Function.bind`)

#### وصف العيب
ادعت المعالجة الحادية عشرة أن «مستدعى نوعه `Function`/`FunctionConstructor` يُقاس بالنوع لا بالاسم» لإغلاق باب إنشاء الدوال من نصوص ديناميكية.
ولكن عند استخدام نمط التقييد المسبق للمنشئ عبر `Function.prototype.bind`:
```typescript
const F = Function.bind(null, "(globalThis as any).j.record('archive_snapshot', {})");
const f = new F();
f();
```
تبيّن ما يلي:
1. تعريف تابع `Function.prototype.bind` في مكتبة TypeScript المعيارية (`lib.es5.d.ts`) يُرجع نوع `any`:
   `bind(this: Function, thisArg: any, ...argArray: any[]): any;`
2. بالتالي، المتغير `F` يصبح نوعه الاستدلالي `any`.
3. عند استدعاء المنشئ `new F()`:
   يقوم كود `scripts/rehydrate_opaque_code.ts` (السطر 124) بفحص:
   ```typescript
   const t = checker.getTypeAtLocation(n.expression);
   const name = checker.typeToString(t);
   if (name === "Function" || name === "FunctionConstructor") { ... }
   ```
   وحيث إن نوع `n.expression` هو `any`، فإن `name` يكون `"any"`، ولا يطابق `"Function"` أو `"FunctionConstructor"`!
4. الدالة المنشأة `f` تحمل أيضًا نوع `any`.
5. استدعاء `f()` هو استدعاء لقيمة من نوع `any` بدون وسيط يومية، فيمر بصمت تام دون اعتراض من الحاجز الساكن.

**الأثر:** ثغرة كاملة تمكن من توليد منشئ دوال ديناميكي من نص ينشئ قيودًا للصنف المعفى، ويمر أخضر تحت سمع الحاجز الساكن وبصره.

### العيب الثالث: `RC07_CHOKEPOINT_UNREACHABLE_BARRIER_ACCEPTED` (حراسة نقطة الاختناق حضورٌ نحوي مجرد بلا تحقق وصول)

#### وصف العيب
ادعت المعالجة الحادية عشرة (البند §4(2) من التعليمات) وضع «حراسة نقطة الاختناق: `StateJournal.read` يجب أن يمر بندائي `assertRehydrateCensus` و`assertExemptionsHold` القانونيين و`rehydrateFromJournal` بنداء `assertExemptionsHold` — وجود النداء في أي موضع آخر من الملف لا يثبتها».

ولكن عند فحص الدالة المسؤولة عن هذه الحراسة في `scripts/rehydrate_barrier_binding.ts` (الأسطر 144–157):
```typescript
export function chokepointGuarded(sf: ts.SourceFile, law: BarrierLaw, owner: string | null, fn: string, barrier: string): boolean | null {
  const body = functionBodyOf(sf, owner, fn);
  if (body === null) return null;
  let found = false;
  const visit = (n: ts.Node): void => {
    if (found) return;
    if (ts.isCallExpression(n) && isLawfulBarrierCall(n, law, barrier)) {
      found = true;
      return;
    }
    ts.forEachChild(n, visit);
  };
  ts.forEachChild(body, visit);
  return found;
}
```
تبيّن أن الفحص هو مجرد تجوال نحوي سطحي (`ts.forEachChild`) يبحث عن أي عقدة `CallExpression` داخل جسم الدالة:
1. لا يفحص قابلية الوصول (`reachability`) إطلاقًا.
2. لا يستخدم جامع الحراس `guardsOf` ولا كاشف التدفق الميت `isReachable` اللذين بُنيا في `scripts/rehydrate_reachability.ts`.
3. ينحدر داخل الكتل الشرطية الميتة (`if (false)`).
4. ينحدر داخل الإغلاقات والدوال السهمية الداخلية غير المستدعاة (`arrow functions` / `closures`).
