### `GN05_CR_ONLY_SEPARATOR_BYPASS`

التعليمة المضافة `tr -d '\r'` تحذف CR ولا تحوّله إلى فاصل أسطر. نتيجة أولى بـLF ثم ثانية فواصلها CR فقط:

```
# tests 2411\n … \n# tests 1\r# pass 0\r# fail 1\r
```

بعد الحذف تصير الثانية سطرًا واحدًا `# tests 1# pass 0# fail 1` لا يطابق `^# tests [0-9]+$`. العدّ = 1. السكربت الحقيقي: **رمز 0**، والمطبوع `tests=2411 · pass=2411 · fail=0` ثم `✓ عدد الاختبارات: 2411 مطابق`. لا `[GN-05]`.

الملف `probes/cr_end_no_lf_mid.tap` و`probes/only_cr_file_second_appended_after_lf.tap`: كلاهما `exit=0` و`GN05=False` و`trusted=True`.

هذا ليس مسبار CRLF الذي أُغلق. CRLF فيه LF فيبقى السطر بعد حذف CR. CR وحده هو الفاصل، وحذفه يُعمي الباب عن النتيجة الثانية. التعليق يدّعي أن السطر الذي ينتهي بـCR يُعدّ. القياس: لا يُعدّ إن كان CR فاصل السطر لا لاحقة قبل LF.

### `GN05_VT_FF_NBSP_EOL_BYPASS`

`sed -e 's/[ \t]*$//'` يقصّ المسافة والتاب فقط. سطر `# tests 1` الذي ينتهي بـVT (`\x0b`) أو FF (`\x0c`) أو مسافة غير قاطعة U+00A0 قبل LF لا يطابق `$`.

الآلية هي آلية العيب المسمّى: المرساة `$` تغفل سطر حصيلةٍ ثانية فينجو رقم الأولى. العلاج قصّ مسافةً وتابًا وCR-قبل-LF، وترك فئة الفراغ التي يهزمها `$` مفتوحة.
