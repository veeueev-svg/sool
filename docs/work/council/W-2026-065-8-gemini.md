### 3. فحص علاج عيب الجلسة 7 والعيوب المكتشفة

في الجلسة 7، قُيِّد العيب `RATE_AMENDMENT_HISTORY_MUTABLE_REFERENCE_ESCAPE`:
> «`RatePolicy.historyOf()` ينسخ المصفوفة فقط ولا ينسخ كائنات `RateDeclaration`، فإسناد `history[0].ratePerMille = 999` من المستدعي يغيّر النسبة الداخلية بلا أمر ملكي.»

ادّعى علاج الجلسة 7 في الالتزام `cce53c3` ما يلي:
> «العلاج: النسخُ عميقةٌ لا سطحية في `historyOf` و`firstOf` و`currentFor` و`effectiveAt` — جميعها تُعيد `{ ...d }`.»

وبالفحص الدقيق والتحليل العدائي للشفرة ومسارات خروج كائنات `RateDeclaration`، تبيّن أن العلاج **ناقصٌ ومعيبٌ جوهريًّا**، ويسرّب المرجع الحي القابل للتعديل من بابين آخرين:

#### العيب الأوّل (حرج ومسقط): `RATE_AMENDMENT_APPEND_MUTABLE_REFERENCE_ESCAPE`
في `src/economy/rate_policy.ts` (السطور 103–109):
```typescript
  append(base: string, ratePerMille: number, declaredAt: number): RateDeclaration {
    const declaration: RateDeclaration = { base, ratePerMille, declaredAt };
    const h = this.history.get(base);
    if (!h) throw new Error(`RATE_BASE_UNDECLARED:${base}`);
    h.push(declaration);
    return declaration;
  }
```
دالّة `append` تنشئ كائن `declaration`، وتدفعه في مصفوفة التاريخ الداخلية `h.push(declaration)`، ثمّ **تُعيده هو نفسه دون نسخ ودون تجميد (`Object.freeze`)**.

ثمّ في `src/economy/tax.ts` (السطور 337–347):
```typescript
    const declaration = this.rates.append(base, newRatePerMille, now);
    const entry = this.deps.audit.append(this.actorId, 'rate_amended', {
      base,
      from: current.ratePerMille,
      to: newRatePerMille,
      previousDeclaredAt: current.declaredAt,
      effectiveFrom: now,
      commandId: command.payload.commandId,
      commandIssuedAt: command.payload.issuedAt,
    });
    return { ok: true, declaration, previous: current, auditId: entry.hash };
```
لاحظ المفارقة:
- حقل `previous: current` محميّ لأن `currentFor` عولجت في الجلسة 7 وصارت تُعيد نسخة `{ ...d }`.
- أمّا حقل `declaration` في نتيجة `amendRate` **فهو المرجع الحي نفسه** المحفوظ داخل مصفوفة `this.history` لسياسة النسب!

**أثر هذا الخرق:**
أي مستدعٍ ينفّذ أمر تعديل ملكي مشروع يحصل على كائن النتيجة `result`. وبمجرد كتابة:
```typescript
result.declaration.ratePerMille = 999;
```
أو العبث بتاريخ السريان:
```typescript
result.declaration.declaredAt = 0;
```
فإن هذا التعديل يمسّ مباشرةً الكائن المخزّن في `this.history.get(base)` في الذاكرة الحية للدولة!
ونتيجة لذلك:
1. `s.revenue.rateFor(base)` يقرأ الكائن المعدّل ويُعيد النسبة المزوّرة (مثلاً 999 أو أي قيمة خارج الحدود مثل 100000).
2. `s.revenue.rateHistoryOf(base)` ينسخ الكائن المعدّل فتظهر النسبة المزوّرة في التاريخ.
3. التقدير الضريبي اللاحق عبر `s.revenue.assess(...)` يستدعي `effectiveAt`، التي تدور في مصفوفة `this.history` فتأخذ النسبة المزوّرة وتضرب الرسم فيها مباشرةً (مثلاً تحصيل 999,000 بدلاً من 40,000)!
4. إذا عُدِّل `declaredAt` إلى الصفر أو تاريخ ماضٍ، يصبح التعديل رجعيًّا ويسري على وقائع وقعت قبل سريان الأمر الملكي، خرقًا لمعيار القبول الصريح: «لا أثرٌ رجعيٌّ».
5. كل هذا التغيير الجوهري يقع **دون أمر ملكي موقع، ودون تفويض من بوابة التاج، ودون تحقق من حدود النسبة (`isValidRatePerMille`)، ودون تدوين قيد `rate_amended` في سجل التدقيق**!

#### إثبات العيب بمسبار مستقل (قابل لإعادة الإنتاج 100%):
```javascript
const assert = require("node:assert/strict");
const { bootstrapState, REVENUE_TARGET } = require("./dist/src/index.js");

const now = Date.now();
const s = bootstrapState({ now });
const cmd = s.king.issueCommand(
  "amend_policy",
  REVENUE_TARGET,
  { kind: "economy", base: "compute_usage", ratePerMille: 40 },
  now + 1000,
);

const res = s.revenue.amendRate(cmd, "compute_usage", 40, now + 1000);
assert.equal(res.ok, true);
assert.equal(s.revenue.rateFor("compute_usage").ratePerMille, 40);

// المستدعي يعبث بالمرجع المُعاد في نتيجة التعديل:
res.declaration.ratePerMille = 999;

// التحقّق: النسبة الداخلية تلوّثت وسُرِّبت!
const current = s.revenue.rateFor("compute_usage");
console.log("Current rate after mutating res.declaration:", current.ratePerMille);
// الخرج المقاس: 999 !

// التحقّق من التقدير المالي:
const levy = s.revenue.assess("compute_usage", "agent:external", 1_000_000, now + 2000, now + 2000);
console.log("Levy assessed:", levy.levy.levied, "with rate:", levy.levy.ratePerMille);
// الخرج المقاس: 999000 بدلاً من 40000 بنسبة 999 في الألف!
```

#### العيب الثاني الملازم: `RATE_POLICY_CONSTRUCTOR_MUTABLE_REFERENCE_ESCAPE`
في `src/economy/rate_policy.ts` (السطور 67–69):
```typescript
  constructor(rates: readonly RateDeclaration[]) {
    for (const rate of rates) this.history.set(rate.base, [rate]);
  }
```
مُنشئ الفئة `RatePolicy` يأخذ مصفوفة `rates` ويدفع كائنات `rate` مباشرةً في مصفوفة التاريخ دون نسخ (`{ ...rate }`). إذا احتفظ أي مستدعٍ بالمرجع الممرَّر إلى المُنشئ (مثل `deps.rates`)، فإن تعديل أي عنصر فيه يغيّر فورًا النسبة الابتدائية في تاريخ السياسة.

### 4. ما وُجد وما لم يُوجد

- **ما وُجد:**
  - تم نسخ المراجع في دوال الاستعلام الأربع (`historyOf`, `firstOf`, `currentFor`, `effectiveAt`).
  - اختبار `**T-53/مجلس 7**` يختبر فقط `rateHistoryOf` ولا يفحص المرجع المُعاد من `amendRate` أو الممرّر للمنشئ.
  - إمكانية تجاوز بوابة التاج وحرس النسبة بالكامل عبر تعديل `result.declaration` الناتج عن `amendRate`.
- **ما لم يُوجد:**
  - لم يُطبَّق مبدأ النسخ العميق أو التجميد (`Object.freeze`) على مخرجات `RatePolicy.append` أو مدخلات `constructor`.
  - لم يُقتَل العيب الجذري لتسريب المراجع القابلة للتعديل (`MUTABLE_REFERENCE_ESCAPE`) في كافة منافذ الوحدة.
