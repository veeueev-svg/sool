## Findings

### The line-172 mechanism is real (partial confirmation)

At the frozen commit, `scripts/check_declaration.sh:53` is `set -euo pipefail` and line 172 is exactly:

```bash
elif printf '%s\n' "$closed_ids" | grep -qx "$t"; then
```

A successful single run prints the closed set as `[T-110 T-16 T-21 T-23 T-31 ]` and exits 0. Under load, that membership test false-negatives and the script prints `[DC-04]` for an id that is in the closed set, then exits 1. Observed targets included T-31, T-23, T-21, T-16, and T-110. Example from `npm test` (not from a hand probe):

```
not ok 912 - T-142: خرجُ التصنيف يُظهر ما كان يسقط صمتًا — مفتوحٌ ومشطوبٌ وبلا صفّ

والمسمّى في الصفوف: ... مشطوبًا مُغلقًا [T-110 T-16 T-21 T-23 ]
1 !== 0
```

T-31 is absent from the closed bracket on that run and present on the green single run. That is the claimed bug, and it is sufficient to fail `declaration_gate` tests and therefore `npm test` / `npm run verify`. Deferring the code fix is consistent with the item being diagnosis-only, and `scripts/check_declaration.sh` is not in the reserved scope. Criterion (2) is met.
