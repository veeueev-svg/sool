## ما وجدت

### RATE_AMENDMENT_HISTORY_MUTABLE_REFERENCE_ESCAPE

`RatePolicy.historyOf()` ينسخ مصفوفة التاريخ فقط (`return h ? [...h] : []`) ولا
ينسخ كائنات `RateDeclaration`. و`RevenueService.rateHistoryOf()` يعيد تلك
المراجع إلى المستدعي العام. لذلك يستطيع أي مستدعٍ JavaScript تعديل إعلان قائم
بلا أمر ملكي، بلا بوابة التاج، وبلا قيد `rate_amended`.

أعدت الإنتاج على البناء الناتج من HEAD:

```js
const { bootstrapState } = require('./dist/src/index.js');
const now = Date.parse('2026-08-23T00:00:00Z');
const s = bootstrapState({ now });
const history = s.revenue.rateHistoryOf('compute_usage');
history[0].ratePerMille = 999;
const levy = s.revenue.assess('compute_usage', 'agent:external', 1000, now, now);
```

والخرج المقاس كان:

```text
before: ratePerMille=25, Object.isFrozen=false
after:  rateHistoryOf('compute_usage')=[999], assessment.ratePerMille=999
```

إذن غُيّرت النسبة المعلنة التاريخية من 25 إلى 999، واستعملها التقدير فعلًا، من
غير `SignedRoyalCommand` ومن غير تحقق `isValidRatePerMille` ومن غير سجل تدقيق.
هذا يخالف مباشرة معيار «لا تعديل بغير أمر ملكي»، ويفسد حفظ تاريخ الإعلان، كما
يتجاوز حد النسبة ذي المصدر الواحد.

النسخ السطحي للمصفوفة لا يكفي هنا؛ يلزم ألا تخرج كائنات التاريخ الداخلية قابلة
للتعديل، مثل إرجاع نسخ عميقة من الإعلانات وإبقاء المخزون الداخلي غير قابل
للتعديل.
