## 5. التحققُ العدائيُّ والمسباراتُ المستقلة

أُجريت مسباراتٌ عدائيةٌ مستقلةٌ داخلَ دليلِ المسباراتِ `/tmp/council3-gemini/probes/` على نسخٍ مستقلةٍ مأخوذةٍ من شجرةِ التجميد، وجاءت النتائجُ كالتالي:

### 5.1 المسبار الأول: إثباتُ عيبِ `COMPUTED_PRODUCER_BYPASSES_DECLARED_WITHOUT_PRODUCER`

- **المسألة**: ينصُّ عقدُ البند (`order.md` §4) صراحةً على:
  > «الإعفاءُ لا يكون بابًا: صنفٌ مُعفًى بحجّةِ «لا مُنتِجَ له» يسقط برمزٍ مُسمًّى إن ظهر له مُنتِجٌ في `src/**` — فالإعفاءُ يُراجَع آليًّا لا يُصدَّق.»
- **التجربة**: في النسخةِ المنفصلة `/tmp/council3-gemini/probes/probe-computed-producer`، أضفنا وحدةً داخلَ `src/data/probe_bypass.ts` تُنتج الصنفَ المعفى `archive_snapshot` عبر تعبيرٍ محسوب:
  ```ts
  interface ProbeJournal {
    record(kind: string, payload: Record<string, never>): void;
  }

  export function emitComputedArchiveSnapshot(journal: ProbeJournal): void {
    journal.record(['archive_snapshot'][0]!, {});
  }
  ```
- **القياسُ المستقل**:
  - `npm run build` خرج بـ 0.
  - `npm run check:rehydrate-census` خرج بـ **0**!
  - مخرج الحاجز أعلن بنجاح كاذب:
    `✓ حصرُ الإرجاع: 23 صنفًا في النطاق كلُّها مُدَّعاة ... 2 بإعفاءٍ قائمِ الموجب`
  - ومسبار الحصر `npm run probe:rehydrate-census` طبع حرفيًّا:
    `· archive_snapshot — declared_without_producer — مُنتِجونَ: لا مُنتِج`
- **التنويع**: جُرّبت تعابير أخرى مثل الدمج النصي `journal.record('archive_' + 'snapshot', {})` والقالب النصي `journal.record(\`archive_\${'snapshot'}\`, {})` — وكلُّها اجتازت الحاجز دون أن يُطلق رمز `[RC-04]`.
- **العلّةُ البنيوية**: دالة `producerSites()` في `scripts/rehydrate_proof.ts` تعتمد على استدعاء `resolvesToKind()`، وهي محلل نحوي جزئي (Partial AST Matcher) يبحث عن حالات محددة مسبقًا: الحرف الصريح، أو معرّف محلي، أو وصول خاصية كائن حرفي، أو فهرس عنصر بمفتاح نصي حرفي. أي تعبير مصفوفي (`['...'][0]`) أو تعبير محسوب يعود فيه المحلل بـ `false`.
- **الأثرُ على النظام**: أصبح بإمكان أي وحدة في `src/**` تدوين الصنف المعفى `archive_snapshot` في اليومية دون أن يُكتب له مستهلك إرجاع، بينما يقرر الحاجز الساكن زيفًا أنّ موجب الإعفاء قائم، مما يعيد إنتاج مشكلة سقوط السجلات عند الإقلاع صمتًا.

### 5.2 المسبار الثاني: تقييمُ «حدِّ الإسنادِ الموضعي» المعلن في الالتزام `19a905f`

- **النصُّ المعروضُ على المجلس**:
  > «حدُّ الإسنادِ اللاحقِ الموضعيِّ: الكتابةُ التي لا يصلُها تتبُّعُ التعريفِ (تصديرٌ ديناميكيٌّ · خارجَ النطاقِ المعجميِّ للدالةِ) تُعاملُ مجهولةَ القيمةِ — وهذا حدُّ تنفيذٍ معلَنٌ يُعرَضُ على مجلسِ الجولةِ الثالثةِ لتقييمِه، لا استثناءُ عقدٍ قرَّرهُ المنفِّذُ.»
- **التقييمُ الموضوعيُّ للحد**:
  1. لا يمكن قبول هذا الحدِّ في صيغته الحالية برهانًا على صحة إعفاء `declared_without_producer`.
  2. في المنطق الرياضي والتحقق البرمجي: **الجهلُ ليس برهانًا على العدم** (Absence of evidence is not evidence of absence).
  3. عندما يفشل المحلل في تتبع القيمة (قيمة مجهولة أو خارج النطاق المعجمي)، فإنّ السلوك الأمني المحافظ (Conservative Failure) يقتضي اعتبار القيمة المجهولة شبهة منتج تلغي الإعفاء وتطلق `[RC-04]`.
  4. لكن الشفرة الحالية في `rehydrate_proof.ts` تفعل العكس تمامًا: إذا كانت القيمة مجهولة، فإنّ `resolvesToKind` تُرجع `false`، فيتحول العجز التحليلي إلى شهادة خلو ("لا منتج")!
  5. ومن ثَمّ، فإنّ هذا الحد بصياغته المنفذة يفرغ معيار القبول من محتواه، ويجعل إعفاء "لا منتج له" نافذة خلفية مفتوحة لأي استدعاء غير محلول.

### 5.3 المسبار الثالث (اكتشافٌ جديد): عيبُ `RC07_PARENTHESIZED_REHYDRATE_CALLEE_BLINDS_GATE`

أثناء فحص دقة حاجز السيادة والترتيب `[RC-07]` في `scripts/check_rehydrate_census.ts`، تم اكتشاف ثغرة جديدة تلتف على شرط الترتيب الزمني قبل أول إرجاع:

- **موضعُ الخلل**: في `scripts/check_rehydrate_census.ts` السطور 205–215:
  ```ts
  walk(bootSf, (n) => {
    if (!ts.isCallExpression(n)) return;
    const callee = n.expression;
    const name = ts.isIdentifier(callee) ? callee.text
      : (ts.isPropertyAccessExpression(callee) ? callee.name.text : '');
    if (name === 'assertRehydrateCensus') { censusCall ??= n; return; }
    if (/^rehydrate[A-Z]/.test(name)) rehydrateCalls.push(n);
  });
  ```
  هذا الكود لا يستدعي `unwrap(callee)`.
- **التجربة العدائية**: في النسخة `/tmp/council3-gemini/probes/probe-rehydrate-callee`، قمنا بتغليف استدعاء دالة الإرجاع الأساسية بالأقواس في `src/index.ts`:
  ```ts
  const rehydrated = journal
    ? (rehydrateFromJournal)(journal, { audit, memory, knowledge, terminationRoll }, 'ministry:data', {
  ```
  ونقلنا استدعاء الحاجز `assertRehydrateCensus` ليصبح **بعد** هذا الاستدعاء مباشرةً (السطر 140).
- **النتيجة المقيسة**:
  - كود الإقلاع الفعلي أصبح يُنفّذ `rehydrateFromJournal` أولاً، ثم يستدعي `assertRehydrateCensus` لاحقًا.
  - لكن عند تشغيل `npm run check:rehydrate-census`:
    - الكاشف اعتبر `name === ''` لأن `callee` عبارة عن `ParenthesizedExpression`.
    - لم تُضف `rehydrateFromJournal` إلى مصفوفة `rehydrateCalls`.
    - بقيت ثلاث دوال إرجاع أخرى لاحقة، فظن الحاجز أن `rehydrateCalls` تضم 3 دوال فقط.
    - قارن موضع `assertRehydrateCensus` بالدوال الثلاث المتبقية فوجده يسبقها!
    - خرج الحاجز بالرمز **0** وطبع:
      `سيادةُ نداءِ الحاجزِ مقيسةٌ على 3 نداءِ إرجاعٍ ...`
      `✓ حصرُ الإرجاع: ... والحاجزُ منادًى قبل أوّلِ إرجاع`!
- **الحكم**: هذا خرقٌ صريح لمعيار القبول الثاني في `order.md` §4:
  > «الإقلاعُ يسقط سقوطًا مُسمًّى برمزِ PERSISTENCE_REHYDRATE_KIND_UNCLAIMED إذا وُجد صنفٌ في النطاقِ بلا دعوى — قبلَ إرجاعِ أوّلِ قيد، لا بعده.»
  الحاجز الساكن عَمِي تمامًا عن نداء الإرجاع الأول لمجرّد تغليفه بأقواس، وأجاز شجرةً تُرجع القيود قبل استدعاء حصر الإرجاع.
