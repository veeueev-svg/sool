## 4. فحص معايير القبول ومسار علاج الجولة 41

### دعوى العلاج المعلنة في الالتزام `9c58aa7`:
أعلن المنفّذ علاج عيبَي الجولة 41 المسمَّيَين (`TAX_LEVY_REJECTED_INPUT_AUDIT_MUTABLE_REFERENCE_ESCAPE` عند gpt، و`TAX_LEVY_REFUSAL_AUDIT_LIVE_REFERENCE` عند grok) بإضافة دالة التعقيم `auditPrimitive` في `src/economy/tax_types.ts`، مع تطبيقها — بحسب دعوى الالتزام والتوثيق — على إغلاقات الرفض الأربعة في `src/economy/tax.ts`، وإعلان الثابت 12: «قيدُ الرفضِ لا يحملُ مرجعًا حيًّا».

### الفحص التحقيقي العدائي للشفرة:
بالفحص المتفحّص لجميع مسارات الرفض في `src/economy/tax.ts`:
1. في `assess()`: تم تطبيق `auditPrimitive(base)` و`auditPrimitive(payer)` و`auditPrimitive(amountBase)` في إغلاق `refuse`، ولا تُمرَّر هذه الحقول في `extra` دون بدائية.
2. في `collect()` و`waive()`: تم تطبيق `auditPrimitive(levyId)` في إغلاق `refuse`، وحقول `extra` منضبطة.
3. **لكن في `amendRate()` (الأسطر 272–294):**
   - عُرّف إغلاق الرفض بالسطور 272–276:
     ```typescript
     const refuse = (reason: string, extra: Record<string, unknown> = {}): RateAmendmentResult => {
       const entry = this.deps.audit.append(this.actorId, 'rate_amendment_refused', {
         base: auditPrimitive(base), requestedRatePerMille: auditPrimitive(newRatePerMille), reason, ...extra,
       });
       return { ok: false, reason, auditId: entry.hash };
     };
     ```
   - ثم في السطور 290–294، عند فحص سلامة النسبة:
     ```typescript
     if (!isValidRatePerMille(newRatePerMille)) {
       return refuse('نسبة غير سليمة: عددٌ صحيحٌ فوق الصفر ولا يتجاوز الألف (حدود المصدر نفسه)', {
         requestedRatePerMille: newRatePerMille,
       });
     }
     ```
   - **الخلل القاتل:** استُدعي `refuse` بتمرير `{ requestedRatePerMille: newRatePerMille }` داخل كائن `extra`.
   - وقواعد نشر الكائنات في جافاسكريبت (`{ a: 1, ...{ a: 2 } }`) تجعل الخاصية الآتية من `extra` **تتجاوز وتلغي (overwrite)** الخاصية السابقة لها في الكائن!
   - ولما كانت `newRatePerMille` غير مفحوصة البدائية قبل هذا السطر، فإن كائن `extra` يحمل المرجع الخام الحي غير المعقم لكائن المستدعي (`newRatePerMille`).
   - هذا التجاوز أبطل بالكامل مفعول تعقيم `auditPrimitive(newRatePerMille)` في هذا المسار، وحقن المرجع الحي لكائن المستدعي مباشرة في تفصيل قيد التدقيق `rate_amendment_refused`!

## 5. العيب المانع المقيس: تسريب المرجع الحي وقتل الإقلاع في مسار رفض تعديل النسبة

### تعريف العيب وتصنيفه:
- **المعرّف:** `RATE_AMENDMENT_REJECTED_INPUT_AUDIT_MUTABLE_REFERENCE_ESCAPE` / `RATE_AMENDMENT_REFUSAL_AUDIT_LIVE_REFERENCE_UNBOOTABLE`
- **الموضع:** `src/economy/tax.ts`، الأسطر 272–276 والأسطر 290–294.
- **التوصيف:** عينُ علّة الجولة 41 ولكنها باقية في مسار رفض تعديل النسبة (`amendRate`). عند تمرير كائن غير بدائي في معامِل النسبة `newRatePerMille` (مثل كائن يحمل دالة `valueOf` أو `toJSON` أو حقولًا إضافية)، يفشل `isValidRatePerMille` ويستدعي `refuse` مع `{ requestedRatePerMille: newRatePerMille }` في `extra`. يتجاوز نشر `...extra` المعقّمَ `auditPrimitive`، فيُخزَّن المرجع الحي لكائن المستدعي في قيد التدقيق الدائم `rate_amendment_refused`.

### الآثار المترتبة المقيسة:
1. **في الذاكرة (Memory Integrity):** عبث المستدعي بحقول كائنه المرفوض بعد انتهاء الاستدعاء (مثل `mutableRate.marker = 'after'`) يؤدي فورًا إلى انكسار سلامة سلسلة التدقيق الخوارزمية وتغيّر نتيجتها من `valid: true` إلى `valid: false` بالعلة `محتوى السجل مُعدَّل`، دون تسجيل أي قيد تدقيق جديد ودون أي أمر ملكي.
2. **على القرص ويومية الحالة (Durable State & Reboot Failure):** عند كتابة هذا القيد إلى يومية حقيقية (`StateJournal`)، تُحسب بصمة القيد في الذاكرة عبر `canonicalize`، بينما يكتب `JSON.stringify` تمثيلًا مختلفًا (يسقط الدوال ويستدعي `toJSON`). عند إعادة إقلاع النظام واستيراد السلسلة عبر `AppendOnlyLog.import`، تفشل مطابقة البصمات ويسقط الإقلاع رامياً استثناءً فادحاً:
   ```text
   نسخة سجل فاسدة: محتوى السجل مُعدَّل عند 39
   ```
   مما يجعل النظام البرمجي غير قابل للإقلاع نهائيًا.
