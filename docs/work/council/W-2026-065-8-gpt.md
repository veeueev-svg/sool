## العيب الحاسم

### RATE_AMENDMENT_RESULT_MUTABLE_REFERENCE_ESCAPE

علاج الجلسة 7 ينسخ مخرجات القرّاء الأربعة، لكنه يترك قناة إرجاع أخرى تُسرّب الكائن
الداخلي نفسه. `RatePolicy.append` ينشئ `declaration`، يدفعه إلى `history` الداخلية،
ثم يعيد المرجع ذاته مباشرةً:

```ts
h.push(declaration);
return declaration;
```

وتستدعي `RevenueService.amendRate` هذا الباب ثم تعيد ذلك المرجع في النتيجة الناجحة:

```ts
const declaration = this.rates.append(base, newRatePerMille, now);
return { ok: true, declaration, previous: current, auditId: entry.hash };
```

بذلك يستطيع من حصل على نتيجة تعديل ملكي صحيحة أن يغيّر `result.declaration` بعد
الإرجاع. التحويل البرمجي لـ`readonly` لا يحمي كائن JavaScript في وقت التشغيل، وهو
بالضبط نموذج التسريب الذي اختبرته الجلسة 7 عبر cast.

### إعادة إنتاج مستقلة

بعد تعديل ملكي صحيح لـ`compute_usage` من `25` إلى `40`، نفذت:

```js
result.declaration.ratePerMille = 999;
const levy = s.revenue.assess(
  'compute_usage', 'agent:external', 1000, now + 2, now + 2,
);
```

وكان الخرج المقاس:

```text
قبل التغيير: canonicalBefore=40، auditBefore=1
بعد التغيير: canonicalAfter=999
historyAfter=[25,999]
assessedRate=999
auditAfter=1
```

إذن يتغير الإعلان الحاكم ويستعمله `assess` فعليًا، من غير أمر ملكي جديد، ولا بوابة
تاج، ولا فحص `isValidRatePerMille`، ولا قيد `rate_amended` إضافي. السجل الأبدي لا
يزال يشهد `to: 40`، فتفترق سياسة التشغيل عن سجل التدقيق إلى أن تعيد عملية إقلاع
لاحقة بناءها. هذا يخالف مباشرة حارس البوابة ومعيار حفظ تاريخ الإعلان.

الاختبار الجديد للجلسة 7 يختبر فقط المرجع الخارج من `rateHistoryOf` قبل أي تعديل
ملكي؛ لذلك يمر رغم أن النتيجة الناجحة لـ`amendRate` تسرب الإعلان الملحق.

### العلاج المطلوب

يجب ألا يعيد `append` كائنًا موجودًا في `history`: بعد الدفع يعيد `{ ...declaration }`
أو تجعل `amendRate` النتيجة `{ ...declaration }`. ويجب إضافة اختبار قبول يعدّل
`result.declaration.ratePerMille` بعد تعديل ملكي ناجح، ثم يثبت أن `rateFor` و
`rateHistoryOf` و`assess` ما زالت ترى النسبة المصرح بها وأن عدد قيود
`rate_amended` لم يتغير. ولإغلاق فئة التسريب كاملةً ينبغي أيضًا نسخ إعلانات الإدخال
في باني `RatePolicy` بدل تخزين مرجع `deps.rates` كما هو.
