### RC14_BINDING_ALIAS_DESTRUCTURE_ESCAPE_GREENS

أنشأت نسخة بوابة مستقلة وحرّفت فقط
`src/data/persistence.ts` فيها إلى:

```ts

  const { run }: { run: any } = box;
  run('globalThis.j.record("archive_snapshot", {})');
  void j;
}
```

هذه ليست صيغة مصطنعة لا تدخل TypeScript: شغلت
`tsc -p <نسخة-المسبار>/tsconfig.json --noEmit` فرجع `TSC_EXIT=0`. وهي امتداد
مباشر للقناة التي يدعي العلاج الرابع عشر أنه أصلحها: التفكيك إلى العضو، لكن
التهيئة هنا معرّف يحيل إلى كائن حرفي، لا الكائن الحرفي في موضع التفكيك نفسه.

شغلت الحاجز المبني من الشجرة المجمدة على هذه النسخة فقط:

```text

  node /tmp/council10-gpt/repo/dist/scripts/check_rehydrate_census.js
GATE_EXIT=0
```

وطبع نجاح الحصر الكامل، بما فيه أن `archive_snapshot` معفى على أساس
`declared_without_producer`. ثم تحققت من الدلالة التشغيلية نفسها، مع حقن
`globalThis.j.record` مراقَب؛ نداء الـ`eval` غير المباشر سجّل فعلاً:

```json
[{"kind":"archive_snapshot","payload":{}}]
```

السبب البنيوي ظاهر في `BindingFlows.scan`: تخصيص أصل العضو للتفكيك لا يحدث
إلا حين يكون `n.initializer` نفسه `ObjectLiteralExpression`. عند
`const { run } = box` يسجل تدفق `run ← box` كله؛ ثم يعيد العرّاف أصل `box`
الكائن الحرفي كـ`data` بدلاً من النزول إلى `box.run` الذي أصله `eval`.
إذن العلاج لا يتتبع «قنوات الربط إلى العضو» كما يدعي حين تمر القناة بمعرّف
واحد مشروع.
