## العيب المانع المقاس

### `TAX_LEVY_MUTABLE_REFERENCE_ESCAPE`

يبقى في مسار البند تسريب مرجع حيّ قابل للتعديل من حال الرسوم:

- `RevenueService.get()` في `src/economy/tax.ts` يعيد مباشرة
  `this.levies.get(levyId) ?? null`.
- `RevenueService.outstanding()` يعيد عناصر `Map` الداخلية نفسها، لا
  نسخًا.
- نوع `Levy` مكتوب بـ`readonly` في TypeScript، لكنه كائن JavaScript
  عادي غير مجمّد؛ لذلك لا يمثل هذا حاجزًا وقت التشغيل.

أعدت مسبارًا مستقلًا على الشجرة المبنية، بلا أمر ملكي ولا بوابة ولا
نداء تعديل أو تحصيل:

```js
const s = bootstrapState({ now: NOW });
const assessed = s.revenue.assess(
  'compute_usage', 'external:compute-provider', 1_000_000, NOW + 1, NOW + 1
);
const escaped = s.revenue.get(assessed.levy.levyId);
escaped.status = 'collected';
escaped.levied = 777777;
escaped.ratePerMille = 999;
```

خرج المسبار المقاس:

```text
sameObject: true
outstanding: 0
report: { assessed: 0, collected: 1, collectedTotal: 777777, ... }
mutated: {
  levyId: "levy:1",
  ratePerMille: 999,
  levied: 777777,
  status: "collected",
  collectedAt: null,
  receiptEntryId: null
}
auditBefore: 38
auditAfter: 38
auditIntegrity: true
LEVY_MUTABLE_REFERENCE_PROBE_EXIT=0
```

فالمرجع المتسرّب بدّل رسمًا مقدرًا إلى «محصّل» وغيّر نسبته ومبلغه
وتقرير الإيراد، من دون أمر ملكي أو تحصيل خزينة أو قيد تدقيق أو تغير
في سلامة سلسلة التدقيق. هذا يتجاوز أبواب `collect` و`waive` و`assess`
كليًا، ويخالف شرط أن تكون حال الرسوم وأثرها موثقين وألا تُعدّل خارج
الباب المعلن. وهو من النوع نفسه الذي عولج سابقًا لإعلانات النسب،
لكنه ما زال موجودًا في `Levy`.

العلاج الأدنى: لا تُرجع `get()` ولا `outstanding()` كائنات `Levy`
الداخلية؛ يجب إرجاع لقطة/نسخة عميقة مناسبة (أو تجميد نسخة) مع اختبار
يعيد مسبار المرجع الحي ويثبت أن التقرير والحالة والتدقيق لا تتغير.
