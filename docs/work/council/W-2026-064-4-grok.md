## 5) صيغ صامتة من العائلة نفسها — العيب الجديد

`REFERENCE_DEF` يُبنى هكذا (من `tests/governance/doc_links.test.ts` على الشجرة المُراجَعة):

```
const CONTAINER = String.raw`(?:[ \t]*(?:>|[-*+]|\d{1,9}[.)])(?=[ \t]|$)[ \t]?)*[ \t]*`;
const REFERENCE_DEF = new RegExp(String.raw`^` + CONTAINER + String.raw`\[[^\]]+\]:\s*(?:<([^<>]*)>|(\S+))`, 'gm');
```

بعد علامة `>` يشترط النمط `(?=[ \t]|$)` — فراغًا أو نهاية سطر. مواصفة CommonMark 0.31.2 §5.1 تقول إن علامة الاقتباس هي `>` مع فراغٍ بعدها **أو** `>` غير متبوعٍ بفراغ، وإن الفراغ بعد `>` يجوز حذفه ([CommonMark Spec 0.31.2](https://spec.commonmark.org/0.31.2/)). تعريف المرجع (§4.7 من المواصفة نفسها) كتلةٌ يجوز أن تكون محتوى الاقتباس. فـ `>[r]: missing.md` تعريفٌ مرجعيٌّ إلى `missing.md` يعرضه العارض، والحارس لا يراه.

الخرج الخامّ على الدالّة المبنيّة نفسها، `exists` يرفض الكلّ:

```
bq-nospace	[]	SRC=">[r]: missing.md"
bq-nospace-indented-1	[]	SRC=" >[r]: missing.md"
bq-nospace-indented-3	[]	SRC="   >[r]: missing.md"
bq-nested-nospace-markers	[]	SRC=">> [r]: missing.md"
bq-nested-nospace-both	[]	SRC=">>[r]: missing.md"
bq-nested-second-nospace	[]	SRC="> >[r]: missing.md"
bq-nospace-with-title	[]	SRC=">[r]: missing.md \"title\""
bq-nospace-angle	[]	SRC=">[r]: <missing file.md>"
bq-tab-after-marker	["missing.md"]	SRC=">\t[r]: missing.md"
bq-list-space	["missing.md"]	SRC="> - [r]: missing.md"
control-bq-space	["missing.md"]	SRC="> [r]: missing.md"
control-plain	["missing.md"]	SRC="[x](missing.md)"
```

الضابط `> [r]: missing.md` (فراغ بعد `>`) يُبلَّغ. الصيغة بلا فراغ، والمزاحة 1–3 فراغات بلا فراغ بعد العلامة، والاقتباس المتداخل `>>` و`> >[r]:`، ترجع `[]`. هذا عمىً صامت من عائلة `DOC_LINK_GUARD_CONTAINER_REFERENCE_BYPASS` لم يغطّه العلاج: العلاج ثبّت علامة الحاوية ثم اشترط فراغًا بعدها، والمواصفة لا تشترط الفراغ بعد `>`.

اسم العيب: `DOC_LINK_GUARD_BLOCKQUOTE_NOSPACE_BYPASS`.

عيب ثانٍ من عائلة التعريف المرجعي، مقيس في التشغيل نفسه:

```
escaped-bracket-label	[]	SRC="[foo\\]bar]: missing.md"
escaped-bracket-label-bq	[]	SRC="> [foo\\]bar]: missing.md"
label-with-escape-only	[]	SRC="[a\\]b]: gone.md"
```

مواصفة CommonMark 0.31.2 (قسم الوسم): الوسم ينتهي عند أول `]` غير مهرَّب بشرطة مائلة ([CommonMark Spec 0.31.2](https://spec.commonmark.org/0.31.2/)). فـ `[foo\]bar]: missing.md` تعريفٌ صالح إلى `missing.md`. النمط `\[[^\]]+\]` يقف عند أول `]` فيهرب التعريف. اسمه: `DOC_LINK_GUARD_ESCAPED_LABEL_BYPASS`.

ما لا أرفض به:

- روابط HTML `<a href="missing.md">` رجعت `[]`. هذا حدٌّ معلن في ملحق العقد (DISC الجلسة 95) ولم يُدَّعَ قياسه. لا أسمّيه عيبًا جديدًا.
- `dest-escaped-space` رجع `[]`. الوجهة العارية في المواصفة لا تضم فراغ ASCII؛ لا أثبت أن العارض يرسمها رابطًا، فلا أرفض بها.
- إزاحة أربعة فراغات خارج قائمة: العلاج يقيسها (إنذار زائد معلن). المسبار `nested-list-4sp` يُبلَّغ. ليس عمىً.

بحث في الشجرة القائمة عن أسطر تبدأ بـ `>[` في ملفات Markdown المتتبَّعة: 14 إصابة، كلها `> [` بفراغ ثم رابط مباشر، لا تعريف `>[r]:`. الحارس الجامع (ok 902) يمرّ لأن الصيغة الصامتة غير موجودة في الشجرة اليوم، لا لأن الحارس يراها. شرط القبول «يُسقط أيَّ رابطٍ مكسورٍ جديد» يسقط بإضافة سطر `>[r]: missing.md` في أي وثيقة محروسة: الخرج المقيس `[]`.
