## Defects

### 1. `DOC_LINK_GUARD_NESTED_PAREN_BYPASS` (silent)

The guard's own comment says a bare destination may contain balanced parentheses. The inline pattern is one level only:

`[^()\s]*(?:\([^()]*\)[^()\s]*)*`

Measured:

- `[x](foo(bar).md)` → `['foo(bar).md']` (one level, seen)
- `[x](foo(bar)(baz).md)` → seen (sequential pairs)
- `[x](foo(bar(baz)).md)` → `[]` (two levels, silent)
- `[x](foo(bar(baz(qux))).md)` → `[]` (three levels, silent)
- `[x](foo(bar(baz)).md "t")` → `[]`
- `![x](foo(bar(baz)).png)` → `[]` (same `](` pattern)
- `[x](<foo(bar(baz)).md>)` → seen (angle-bracket form only)

CommonMark 0.31.2, which this file already cites for the blockquote fix, requires implementations to support at least three levels of nested balanced parentheses in a bare link destination. GitHub renders `[x](foo(bar(baz)).md)` as a link. A new broken link in that form passes `npm test` with no report. This is not in the declared limits (HTML `<a href>`, or a 4-space indent over-warning). Reference definitions happen to catch the same destination via `\S+`; inline links do not. The acceptance criterion "the guard drops any new broken link" is not met.
