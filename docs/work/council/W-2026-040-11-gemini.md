## 5. التحقق العدائي واكتشاف العيوب القاتلة (Adversarial Probing & Escapes)

تم إنشاء بيئة فحص عدائية مستقلة تماماً في المسار المعزول `/tmp/council11-gemini/probes`، تعتمد على استدعاء أداة فحص الإحصاء `check_rehydrate_census.js` باستخدام متغير البيئة الحاكم `SOOL_CHECK_ROOT` على شجرة كود مستقلة، دون أي مساس بالنسخة النظيفة `REPO`.

صُممت مجموعة مسبارات عدائية متقدمة لاختبار ثغرات دلالية (Semantic Blindspots) في نموذج تحليل TypeScript التجريدي AST:

- التحقق من دوال الجلب للكائنات والأصناف (Getters): تم التقاطها (`[RC-14]`).
- التحقق من مولدات `yield*`: تم التقاطها (`[RC-14]`).
- التحقق من العمليات الثنائية وعوامل الدمج المنطقي: تم التقاطها (`[RC-14]`).

ومع ذلك، كشف التحقيق الجنائي المعمق في ملفات `scripts/rehydrate_value_views.ts` و`scripts/rehydrate_binding_flows.ts` عن **ثلاثة عيوب هيكلية قاتلة نجا منها الكود التنفيذي المحظور تماماً وعبر الحاجز خلسة برمز نجاح EXIT=0:**

---

### العيب الأول المسمى: `CLASS_STATIC_METHOD_EXEC_ESCAPE`
#### طبيعة العيب:
الهروب التنفيذي عبر المناهج الساكنة للأصناف (Class Static Methods).
#### الكود التنفيذي المخترق:
```typescript
class Box {
  static run(): any {
    return eval;
  }
}
Box.run()('globalThis.j.record("archive_snapshot", {})');
```
#### نتيجة القياس التجريبي:
- **رمز الخروج:** `0` (نجاح بدون أي اعتراض!).
- **خرج الحاجز:** صمت تام، لم يتم إطلاق الرمز `[RC-14]` إطلاقاً، وتم السماح للشيفرة بالمرور إلى حزمة إعادة الترطيب.
#### التحليل الجذري في الكود المصدري:
في الملف `scripts/rehydrate_value_views.ts`، السطور 82-108:
```typescript
function materializeViews(expr: ts.Expression, ctx: ViewContext): ValueView[] {
  // ...
  if (ts.isNewExpression(target)) {
    const classDecl = classDeclOf(target.expression, ctx);
    // ... constructs class view
  }
  // ...
}
```
الحاجز يشترط حصر المنظور في تعابير إنشاء الكائنات (`ts.isNewExpression`). وعند استدعاء منهج ساكن مثل `Box.run()`، يكون التعبير الهدف للاستدعاء هو وصول لخاصية على معرّف الصنف (`ts.isPropertyAccessExpression` على `Box`). لا يقوم `materializeViews` ببناء منظور صنف للمعرّف `Box`، بل يعامله كمعرّف عادي ويعيد مصفوفة منظورات فارغة `[]`. وبذلك تعجز دالة `resolveMemberValue` عن استرجاع جسم المنهج الساكن وما يعيده، فيمر استدعاء `eval` دون أي اعتراض!

---

### العيب الثاني المسمى: `CLASS_INHERITANCE_METHOD_EXEC_ESCAPE`
#### طبيعة العيب:
الهروب التنفيذي عبر وراثة الأصناف (Class Inheritance / Prototype Chain Escape).
#### الكود التنفيذي المخترق:
```typescript
class Base {
  run(): any {
    return eval;
  }
}
class Derived extends Base {}
new Derived().run()('globalThis.j.record("archive_snapshot", {})');
```
#### نتيجة القياس التجريبي:
- **رمز الخروج:** `0` (نجاح واختراق كامل للحاجز).
- **خرج الحاجز:** لم يُسجل أي خطأ ولم يُلتقط الرمز `[RC-14]`.
#### التحليل الجذري في الكود المصدري:
في `scripts/rehydrate_value_views.ts`، السطور 156-170، عند فحص أعضاء الصنف في دالة `classDeclOf`:
```typescript
function classDeclOf(expr: ts.Expression, ctx: ViewContext): ts.ClassDeclaration | undefined {
  const id = ts.isIdentifier(expr) ? expr : undefined;
  if (!id) return undefined;
  // returns classDecl from bindings
}
```
ثم في دالة `resolveMemberValue` (السطر 202):
```typescript
case "class": {
  for (const member of view.node.members) {
    if (ts.isMethodDeclaration(member) && ts.isIdentifier(member.name) && member.name.text === name) {
      return member;
    }
  }
}
```
يبحث الحاجز حصراً في الأعضاء المباشرة للصنف المنشأ `view.node.members`. وعندما يرث الصنف المشتق `Derived` المنهج `run` من صنف القاعدة `Base` عبر `extends Base` (`heritageClauses`)، لا يقوم المحلل بزيارة الصنف الأب، فيعتبر المنهج `run` غير موجود في `Derived`، فتُعاد القيمة `undefined`، ويمر استدعاء التابع الموروث المنفّذ لـ `eval` بسلام تام!

---

### العيب الثالث المسمى: `OBJECT_ASSIGN_TARGET_MUTATION_ESCAPE`
#### طبيعة العيب:
الهروب عبر تعديل المتغير الهدف في دمج الكائنات (Object.assign Target Mutation Escape).
#### الكود التنفيذي المخترق:
```typescript
const target: any = {};
Object.assign(target, { a: 1 }, { run: eval });
target.run('globalThis.j.record("archive_snapshot", {})');
```
#### نتيجة القياس التجريبي:
- **رمز الخروج:** `0` (نجاح كامل وتسلل للشيفرة المحظورة).
- **خرج الحاجز:** صمت تام وخروج برمز 0 دون كشف `[RC-14]`.
#### التحليل الجذري في الكود المصدري:
في الملف `scripts/rehydrate_binding_flows.ts` والملف `scripts/rehydrate_value_views.ts`، تم تصميم دعم `Object.assign` ليتعامل فقط مع ناتج الاستدعاء المباشر إذا كان الاستدعاء نفسه هو التعبير المادي للمتغير:
```typescript
// const x = Object.assign({}, { run: eval }); // هذا يتم التقاطه
```
ولكن عندما يكون الهدف متغيراً سابق التعريف تم تعديله كأثر جانبي (Side Effect Mutation):
```typescript
const target: any = {};
Object.assign(target, ...);
```
فإن `target` يبقى مسجلاً في قاموس تدفقات الربط `flowsOf(target)` ككائن حرفي فارغ `{}` بحسب تعريفه الابتدائي. لا يتتبع المحلل الثابت استدعاءات `Object.assign(target, ...)` اللاحقة لتحديث حالة منظور الربط لـ `target`. وبالتالي عند وصول الحاجز إلى `target.run()`، يرى أن `target` كائن فارغ ليس له خاصية `run`، فيتجاهله تماماً ويسمح بتنفيذ `eval`!

## 6. تقييم معايير القبول وحكم العقد (RULE-020 & Acceptance Criteria)

ينص عقد البند W-2026-040 في الفقرة الرابعة (§4) بصرامة لا تقبل الشك:
> **«الإعفاءُ لا يكونُ باباً»** — الظهورُ في `src/**` مقيسًا على بوابةِ الدمجِ، وكلُّ علاجٍ يُقيسُ بإسقاطِ المسباراتِ المسماةِ، والعددُ يكبرُ بكلِّ جولةٍ ولا يُجمَّد.

إن حاجز إعادة الترطيب (Rehydrate Census Barrier) هو خط الدفاع السيادي الأول والأساسي لمنع حقن واستدعاء أي شيفرة تنفيذية دخيلة في مرحلة إعادة ترطيب السجلات واليوميات. 

وعلى الرغم من أن العلاج الخامس عشر (Remedy 15) بذل جهداً مشهوداً في ردم ثغرات الجولة العاشرة الـ 16 المباشرة وتطوير بنية منظورات القيمة، إلا أن **التحقق العدائي المستقل أثبت بما لا يدع مجالاً للشك أن الجدار ما زال نفاذاً وقابلاً للاختراق عبر بنيات لغوية قياسية بديهية في لغة TypeScript:**
1. استخدام المناهج الساكنة للأصناف (`CLASS_STATIC_METHOD_EXEC_ESCAPE`).
