- **وصف العيب في الجلسة 5:**
  في الجلسة 5، كُشف أن `RatePolicy.restore` يتخطى بصمت أي شاهد `rate_amended` يحمل معرّف أمر مكرّر `commandId` حتى لو اختلفت النسبة وتاريخ السريان أو الوعاء، ممّا يمحو الشاهد المتعارض في السجل صمتًا دون رمي خطأ.
- **التحقق من العلاج:**
  1. في `src/economy/rate_policy.ts`:
     تم فصل سجل المعرّفات المنفذة `executed: Set<string>` عن سجل الحمولات المستعادة `restored: Map<string, RateAmendmentRecovery>`.
     وعند مصادفة معرّف سبق تنفيذه، يُسترجع الشاهد الأصلي من `restored`:
     ```ts
     if (this.executed.has(a.commandId)) {
       const first = this.restored.get(a.commandId);
       if (first && (first.base !== a.base || first.ratePerMille !== a.ratePerMille || first.declaredAt !== a.declaredAt))
         throw new Error(`RECOVERY_RATE_COMMAND_CONFLICT:${a.commandId}`);
       continue;
     }
     ```
     إذا كان الشاهد مكررًا بنفس الحمولة تمامًا (إعادة أمينة idempotent)، يتم تخطيه بأمان؛ وإذا كان هناك تعارض في الوعاء أو النسبة أو تاريخ السريان، يتم رمي الخطأ الصريح `RECOVERY_RATE_COMMAND_CONFLICT:<commandId>`.
