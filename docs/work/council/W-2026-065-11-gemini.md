### ب) فحص العيب الثاني: `RATE_AMENDMENT_EFFECTIVE_AT_MUTABLE_OBJECT_ESCAPE` (grok)
- **الحال:** أُغلق تمامًا (CLOSED).
- **التحليل في الكود:**
  1. في `src/economy/rate_policy.ts`، أُضيفت الدالة الحارسة `assertPrimitiveDeclaration`:
     ```ts
     function assertPrimitiveDeclaration(rate: RateDeclaration): void {
       if (typeof rate.base !== 'string' || rate.base.trim() === '' ||
           !finite(rate.ratePerMille) || !finite(rate.declaredAt)) {
         throw new Error('RATE_DECLARATION_NOT_PRIMITIVE');
       }
     }
     ```
     حيث `finite` يتحقق بدقة من أنّ `typeof v === 'number' && Number.isFinite(v)`.
     هذه الدالة تُستدعى في المُنشئ لكل عنصر، وفي `append` لكل إعلان ملحق. فكل كائن يحتوي دالة `valueOf` أو `toString` أو حقولاً غير أولية أو قيماً غير محددة (`NaN` / `Infinity`) يُرفض فوراً برمية `RATE_DECLARATION_NOT_PRIMITIVE`.
  2. في `src/economy/tax.ts` داخل `amendRate`، وُضعت حراسة صريحة لنوع `now` قبل أي مقارنة إكراهية:
     ```ts
     if (typeof now !== 'number' || !Number.isFinite(now)) {
       return refuse('تاريخُ السريانِ رقمٌ محددٌ لا كائنٌ يُكرَه عند المقارنة — وذاك مرجعٌ حيٌّ يحرّك السريان بلا أمرٍ ملكي');
     }
     ```
  3. في `RatePolicy.restore`، فُحصت جميع الحقول المنقولة (`declaredAt` · `from` · `previousDeclaredAt` · `commandIssuedAt`) بفحوصات صارمة تمنع تمرير أي كائن غير بدائي.
- **القياس بمسبار خارجي مستقل:**
  - تمرير كائن ذي `valueOf` في `declaredAt` إلى مُنشئ `RatePolicy` رَمى `RATE_DECLARATION_NOT_PRIMITIVE`.
  - تمرير كائن ذي `valueOf` في `ratePerMille` رَمى `RATE_DECLARATION_NOT_PRIMITIVE`.
  - تمرير كائن في `base` ذي `toString` أو نص فارغ رَمى `RATE_DECLARATION_NOT_PRIMITIVE`.
  - تمرير `NaN` أو `Infinity` رَمى `RATE_DECLARATION_NOT_PRIMITIVE`.
  - تمرير كائن ساعة `{ valueOf: () => T1 }` كـ `now` إلى `amendRate` رُفِض بـ `ok: false` مع سبب صريح ولم تتغير النسبة وبقي التاريخ سليماً.
- اجتاز الاختباران التوكيديان `T-53/مجلس 9أ` و`T-53/مجلس 9ب` بنجاح تام.
