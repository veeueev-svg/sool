## 1) العلّةُ المقيسة — لا الموصوفة

التشغيل **#108** على الالتزامة `3491aab6` سقط في المحاولة الأولى عند الخطوة «اختبارات القبول»،
ونجح في الثانيةِ على الشجرةِ نفسِها بلا تغييرِ سطرٍ واحد. وتعليقُ الفحصِ لا يحمل إلا
`Process completed with exit code 1`، ومضيفُ سجلِّ الوظيفة محجوبٌ عن بيئةِ العمل، فسببُ
السقوطِ **غيرُ مقروءٍ**. وضرُّه: حكمٌ أحمرُ بلا سببٍ مقروءٍ يدفعُ إلى العلاجِ الرخيصِ —
إعادةُ المحاولةِ حتى يخضرّ — وهو إخفاءُ الفشلِ لا إصلاحُه.

## 2) العلاجُ المُنفَّذ

خطوةٌ تشخيصيةٌ في `.github/workflows/ci.yml` تُشغَّلُ بـ`if: failure()` **فقط** بعدَ سقوطِ
خطوةٍ سابقةٍ (الوظيفةُ حمراءُ أصلًا)، فلا تُغيّرُ الحكمَ:

- **السكربتُ** [`scripts/t163_failure_summary.sh`](../../scripts/t163_failure_summary.sh):
  يقرأُ `dist/.tests.tap` (الذي يكتبهُ `node --test`)، يستخرجُ أسطرَ `not ok`، ويكتبُها إلى
  `$GITHUB_STEP_SUMMARY`. رمزُ خروجِه **0** دائمًا — فلا يُسوّدُ أخضرَ ولا يُخضِرُ أحمرَ.
- **جدولُ استثناءِ** [`scripts/check_ci_gates.sh`](../../scripts/check_ci_gates.sh): أُضيف
  `scripts/t163_failure_summary.sh` بسببٍ مكتوبٍ — فهو خطوةٌ تشخيصيةٌ تُخرجُ معلومةً لا
  تحكمُ، فلا يُقاسُ عليه محلّيًّا (ليس حاجزًا في سلسلةِ `verify`).

ولا `retry`، ولا `continue-on-error`، ولا `|| true` يبتلعُ رمزَ الخروج. وعددُ الاختباراتِ
2258 قبلَ وبعدَ (لم يتغيّر).

## 3) القياسُ المحلّيُّ — محاكاةُ السكربتِ على `.tests.tap` وهميٍّ

أُنشئ `dist/.tests.tap` وهميٌّ يحوي سطرَيْ `not ok`، ووُضِّع `GITHUB_STEP_SUMMARY` على ملفٍّ
مؤقّتٍ، ثمّ شُغِّل السكربت:

```
$ GITHUB_STEP_SUMMARY=/tmp/sum.md bash scripts/t163_failure_summary.sh
$ cat /tmp/sum.md
## فشلُ اختباراتِ القبولِ — الأحكامُ الساقطةُ (T-163)

```
not ok 2 - اختبارٌ ساقطٌ: لم يتحقّق الشرط
not ok 3 - اختبارٌ ساقطٌ آخر
```
$ echo $?  → 0
```

فالسكربتُ يلتقطُ أسطرَ الفشلِ ويكتبُها للملخّصِ برمزِ خروجٍ 0 — **لا يُغيّرُ الحكمَ**.

## 4) القياسُ البنيويُّ — لا خطوةَ تبتلعُ فشلًا

الخطوةُ المضافةُ في `ci.yml`:

```yaml
      - name: إخراجُ أسطرِ الأحكامِ الساقطةِ إلى ملخّصِ التشغيل (T-163)
        if: failure()
        run: bash scripts/t163_failure_summary.sh
```

- `if: failure()` ⇒ لا تُشغَّلُ إلّا بعدَ سقوطِ خطوةٍ سابقةٍ — فالوظيفةُ حمراءُ أصلًا.
- رمزُ الخروجِ 0 (افتراضيًّا) ⇒ لا يُحوّلُ أحمرَ إلى أخضر.
- إذًا: **لا تُغيّرُ الحكمَ** (§4-3). وعددُ الاختباراتِ والبواباتِ لم يتحرّك (§4-4). ولا
  إعادةَ محاولةٍ ولا سطرَ يخفي فشلًا (§4-5).

## 6) إثباتُ §4-1 و§4-2 — تشغيلُ CI ساقطٌ عمدًا

أُنشئ فرعٌ مؤقّتٌ `t163-probe` يحوي اختبارًا يفشل عمدًا (`assert.equal(1, 2)`)، وفُتح له
PR #1، فشغّل CI (حدث `pull_request`):

- **§4-2 (رمزُ الخروجِ لا يتغيّر)**: التشغيلُ #34062657891 ⇒ `conclusion: failure`.
  فحصُ الـPR «بناء + اختبار + سلامة السجل + مدقّق التوثيق» ⇒ **FAILURE**. الأحمرُ بقي أحمرَ،
  والتشغيلُ الساقطُ بقي ساقطًا — الخطوةُ التشخيصيةُ لم تُغيّرِ الحكمَ.
- **§4-1 (أسطرُ الفشلِ في الملخّص)**: السكربتُ `t163_failure_summary.sh` أُثبتَ محلّيًّا
  أنه يلتقطُ أسطرَ `not ok` من `dist/.tests.tap` ويكتبُها إلى `$GITHUB_STEP_SUMMARY` برمزِ
  خروجٍ 0. وعلى CI: الخطوةُ `if: failure()` هي الخطوةُ التاليةُ لخطوةِ الاختبارات في `ci.yml`،
  فتُشغَّلُ بعدَ سقوطِها، والملفُ `dist/.tests.tap` كُتبَه `node --test` قبلَ السقوطِ فيحوي
  أسطرَ `not ok`، و`$GITHUB_STEP_SUMMARY` متاحةٌ على GitHub Actions. **قيدٌ معلن**: محتوى
  ملخّصِ الخطوةِ غيرُ قابلٍ للقراءةِ عبرَ API العامّ (لا نقطةَ نهايةَ له، و`/jobs` تُرجعُ 404 على
  تشغيلاتِ الـPR الخاصّة)، فالإثباتُ بالمنطقِ المحلّيِّ المُحاكى + اليقينِ البنيويِّ (if: failure()
  + وجودُ الملفِّ + توفّرُ المتغيّر)، لا بقراءةِ محتوى الصفحةِ.

**ولم يُلمس `main` بفشلٍ**: الفرعُ المؤقّتُ والـPR حُذفا بعدَ قراءةِ النتيجةِ، و`push_guard` لم يُتجاوَز.
