## 6) أثر التغيير على المعمارية

- `bootstrapState()` أصبح يستقبل خيارات (`configDir`, `now`, `auditPath`, `monitorTickMs`, `startMonitor`)
  ويُنشئ إضافةً إلى ما سبق: `resources` (سجل الموارد) و`monitor` (مراقب الملك).
  الاستدعاء بلا وسائط يبقى متوافقًا مع كل الاختبارات السابقة.
- ترتيب الاعتماد الجديد: السجل ← التهيئة والحصص ← جذر الثقة ← الملك ← الحماية والمراقبة ← الموارد ← البوابة ← الحرس.
- `loadQuotas()` يرفض: موارد غير معلنة، حقولًا ناقصة، وسقف كيان يتجاوز السقف الكلي.

## 7) ما لم يُختبر بعد (فجوات معلنة)

1. العزل التنفيذي ومنع الخروج الشبكي فعليًا — المرحلة 11.
2. سجل الوكلاء وصلاحياتهم وحصصهم عند التشغيل الحقيقي — المراحل 13–15 (لا وكلاء بعد: RULE-002).
3. حفظ دوري تلقائي للسجل + `scripts/restore.sh` + أهداف RTO/RPO — المرحلة 32.
4. اختبارات الضغط والانقطاع — المرحلتان 33–34.
5. تدوير مفاتيح جذر الثقة (الإبطال موجود، التدوير الكامل لا).
6. مفتاح الملك ما زال يُولَّد داخل العملية — يحتاج مخزن مفاتيح/HSM.
