# docs/audit/measurements/phase-39-T120.txt — إلزامُ الثبات في التشغيل الاتحادي (المرحلة 39، البند T-120)
# المالك: وزارة الإنتاج · القارئ: docs/test-reports/phase-39.md §33 · RULE-005 وRULE-007
#
# السؤالُ المقيس: هل تستطيع الدولةُ أن تعمل في وضع الإنتاج بلا مجلدِ ثبات؟
# الحكمُ المطلوب: لا. وغيابُ الثبات حادثٌ حرج يُوقف المسالك السيادية (فشلٌ مغلق).
#
# ═══ موضعُ الإلزام: التهيئة لا الشفرة (RULE-005) ═══
# config/production.yaml            : policy.scanners        += "durable_state"
# config/production.yaml            : policy.severity.critical += "state_not_durable"
# deploy/production/manifest.yaml   : scanners               += durable_state
#   (البيانُ والتهيئةُ يجب أن يتطابقا حرفًا بحرف، وإلا سقط الإقلاع — لا انحرافَ صامت.)
# src/kernel/config/production_policy.ts : الماسحُ مضافٌ إلى PRODUCTION_REQUIRED_SCANNERS،
#   والحادثُ مضافٌ إلى PRODUCTION_MUST_BE_CRITICAL — فلا يستطيع مشغّلٌ تخفيفَ خطورته بتهيئة.
#
# ═══ الدليلُ الميداني: الأثرُ لم يُفتعل، بل ظهر أولًا كسقوطٍ حقيقي ═══
# عند تفعيل الماسح، سقطت 3 اختباراتِ قبولٍ قائمة برسالة:
#   «الدولة في حالة إيقاف: حادث حرج في التشغيل الاتحادي: state_not_durable»
# وهذا هو السلوكُ المقصود بعينه: مهادُ الاختبار كان يُقلع بلا مجلدِ ثبات.
# الإصلاحُ كان في المهاد لا في السياسة: tests/production/helpers.ts صار يُنشئ مجلدَ
# حالةٍ مؤقتًا ويُقلع به. **لم تُخفَّف خطورةُ الحادث، ولم يُنزع الماسح من المشترطين.**
#
# ═══ الفحوصُ الأربعة (tests/production/durable_state_scanner.test.ts) ═══
# ok 1 — لا وسيط دائم ⇒ حادثُ ثبات يُرفع مرة واحدة لا في كل مسحة (لا إغراقَ سجل)
# ok 2 — يوميّة مُتحقَّقة ⇒ لا حادث؛ وانكسارُ سلسلتها يُرفع حادثًا باسم الملف
# ok 3 — الحادثُ يُرفع مرةً أخرى بعد إصلاحٍ ثم انكسارٍ جديد: العدّادُ لا يُقفل على الأبد
# ok 4 — الثباتُ مشترطٌ ومعلنٌ وحرج في التهيئة نفسها لا في الشفرة
# النتيجة: 4/4 ناجحة.
#
# ═══ حدُّ هذا القياس (RULE-008) ═══
# الماسحُ يشهد على وجود يوميّةٍ وسلامةِ سلسلتها لحظةَ المسح. لا يشهد على مزامنة
# القرص إلى وسيطٍ خارج الجهاز، ولا على نسخةٍ احتياطية بعيدة — تلك مسؤوليةُ
