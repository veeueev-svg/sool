§2) العلّةُ الأولى: الحذفُ لا يُعبَّر عنه — رمزُ الخروج 128
--------------------------------------------------------------------------------

    في جذرٍ مؤقّتٍ: أساسٌ فيه keep.txt وgone.txt وboth.txt، ثمّ التزامةٌ محلّيّةٌ
    تُعدّل both.txt و**تحذف gone.txt**:

      $ git show HEAD:gone.txt > /dev/null 2>&1 ; echo $?
      128

      $ git diff --name-only HEAD^ HEAD
      both.txt
      gone.txt                ← **لا يقول أيُّها محذوف**

      $ git diff --name-status HEAD^ HEAD
      M   both.txt
      D   gone.txt            ← الحقيقةُ هنا، والإجراءُ القديم لم يكن يقرؤها

    فالإجراءُ القديم يبني عناصرَ الشجرةِ من `git diff --name-only` ثمّ يقرأ محتوى كلِّ
    مسارٍ بـ`git show HEAD:<مسار>` — **وهو يسقط برمز 128 على المسارِ المحذوف**، فإمّا
    تنهار الأداةُ وإمّا (لو تُجوهل الخطأ) يمضي الدفعُ بلا تعبيرٍ عن الحذف.

§3) العلّةُ الثانية: لا مقابلةَ أبٍ — فتباعدٌ صامتٌ وضياعُ تعديلِ البعيد
--------------------------------------------------------------------------------

    مُحاكاةُ الإجراءِ القديم **محلّيًّا بلا شبكة** بدلالةِ git نفسِها، فـ`base_tree`
    في الـAPI هو عينُ `git read-tree`، وعنصرُ الشجرةِ هو عينُ
    `git update-index --cacheinfo`:

      البعيدُ تقدَّم بالتزامةٍ عدّلت both.txt وأضافت onlyremote.txt.
      والمحلّيُّ من الأساسِ نفسِه عدّل both.txt وحذف gone.txt.

      $ git rev-parse HEAD^^{tree}   (شجرةُ أبِ الالتزامةِ المحلّيّة)
      317ef2ede36440adb269786d96a70a151fccd685
      $ (شجرةُ رأسِ البعيد)
      ad8283910f734d71507698928267eb275ad15c98
      ⇒ **مختلفتان**، والإجراءُ القديم لا يقابلهما ويدفع بـparents=[رأسُ البعيد].

      $ git read-tree <شجرةُ البعيد> ; git update-index --cacheinfo <عناصرُ المحلّيّ> ;
        git write-tree
      c3a8336d8523552f7f08ad256920a3f8d283046e

      $ git cat-file -p <الناتج>:both.txt
      both-LOCAL              ← **تعديلُ البعيدِ ضاع صامتًا** (كان both-REMOTE)
      $ git cat-file -e <الناتج>:gone.txt ; echo $?
      0                       ← **المحذوفُ باقٍ**: الحذفُ لم يُعبَّر عنه
      $ git cat-file -e <الناتج>:onlyremote.txt ; echo $?
      0                       ← ما لم يلمسه المحلّيُّ نجا (base_tree)

    الحصيلة: **رمزُ خروجِ الإجراءِ القديم 0 ولا تحذيرَ**، والالتزامةُ المدفوعةُ تُنسب
    إلى رأسِ البعيدِ **وهي لم ترَ تعديلَه قطُّ**. فليست هذه مخاطرةً نظريّة: هي ضياعُ
    تعديلٍ مقيسٌ في جذرٍ حقيقيٍّ برمزِ خروجٍ وبمحتوى ملفٍّ يُقرأ.

§8) حدٌّ قيس في أوّلِ دفعٍ حقيقيّ — يُروى كما وقع (RULE-007)
--------------------------------------------------------------------------------

    شُغِّلت الأداةُ بـ`--push` على هذه الالتزامةِ نفسِها فأذنت خطّتُها:

      رأسُ البعيد : 126431c1… · شجرتُه 5830c6b4…
      شجرةُ HEAD^ : 5830c6b4…  ✓ تُطابق شجرةَ البعيد — لا تباعد
      المساراتُ المتغيّرة: 10 (7 M/A نصًّا · وكلُّها 100644)

    ثمّ سقطت في رفعِ أوّلِ ملفّ:

      ✗ [PA-04] نداءُ POST …/git/blobs لم يتمّ: spawnSync curl E2BIG

    **والسقوطُ حكمٌ صحيحٌ على علّةٍ في الأداةِ لا في البعيد**: كان جسدُ الطلبِ يُمرَّر
    مُعامِلًا (`-d <نصّ>`)، ومحتوى ملفٍّ كبيرٍ مُرمَّزًا بـbase64 **يتجاوز حدَّ argv**. فصار
    يُمرَّر بالمَدخلِ (`-d @-` مع `input`) فلا سقفَ على حجمِ الملفّ. **فالحدُّ قيس ولم
    يُفترض**، وهذا وجهٌ ثالثٌ من علّةِ البند: أداةٌ تُعاد تأليفًا كلَّ جلسةٍ لا تتعلّم من
    سقوطِها، **وأداةٌ في المستودعِ تحمل درسَها في تعليقٍ فوق سطرِه**.

    ولا يُقاس هذا الحدُّ باختبارٍ في هذا الملفّ: هو **حدُّ بيئةٍ في طبقةِ الشبكة** (طولُ
    مُعامِلٍ في نداءِ عمليّة) لا حكمٌ في المخطِّط، وقياسُه يقتضي نداءً خارجيًّا — فيُعلَن
    هنا كما أُعلن `PA-09`، ودليلُه §9.

§9) تصحيحُ شهادةِ §7 بعد إصلاحِ §8 — الرقمُ يُقرأ كما وقع لا كما يُشتهى
--------------------------------------------------------------------------------

    شهادةُ §7 (`EXIT=0` · 2170/2170) قيست **مرّتَين** على الأداةِ **قبل** إصلاحِ `E2BIG`.
    وبعد الإصلاح شُغِّلت السلسلةُ مرّتَين فردَّت **مرّتَين**:

      npm run verify ⇒ EXIT=1 · # pass 2169 · # fail 1
      not ok 1414 - قبول 37: تشغيل اتحادي دائم …
        خروق: PROD_SUPERVISION_GAP   (dist/tests/production/production_lifecycle.test.js)

    **وهذا هو عينُ العيبِ المُعلَنِ في `W-2026-004` (حالُه `BLOCKED`)**: أعتابٌ زمنيّةٌ
    مطلقةٌ تُقاس بساعةِ الحائطِ فتردُّ تحت الحِمل. **وقيس أنّه لا يتعلّق بتغييرِ هذا البند**:

      الملفُّ منفردًا والتغييرُ حاضر  : 3 مشياتٍ ⇒ pass 3 · fail 0 (ثلاثًا)
      الملفُّ منفردًا والتغييرُ مُخزَّن : مشيتان ⇒ pass 3 · fail 0 (مرّتَين)

    فالسقوطُ يقع **في السلسلةِ الكاملةِ المتوازيةِ وحدَها** (حِملٌ) ولا يقع منفردًا، **وهو
    نفسُه بحضورِ التغييرِ وبغيابِه**. ولم يُلمس منه حرفٌ: نطاقُه محجوزٌ لبندٍ `BLOCKED`،
    **والتحايلُ على عيبٍ محجوزٍ لغيري ممنوعٌ ولو كان يُخضِّر رقمي**.

    **فالحكم**: سلسلةُ التحقّقِ لهذا البند **`EXIT=0` مُقاسٌ قبل إصلاحِ `E2BIG`**، وبعده
    **`UNVERIFIED` بسببِ عيبٍ خارجَ النطاقِ لا بسببِ الشفرةِ الجديدة** — وأحكامُ البندِ
    الثلاثةَ عشرَ خضراءُ في الحالَين (13/13 مرّتَين، قبل الإصلاحِ وبعده). ودليلُ الدمجِ
    النهائيُّ هو شهادةُ CI في §10 لا دعوى محلّيّة.

§10) شهادةُ الدمج — ودليلُ `PA-09` فعلًا لا قولًا

      ✓ دُفع: 21557f450a76d47c10ee196079363b5da6470095
        الشجرةُ 7c7fd50edb086b70024c0a468b88071f689b25dd **تُطابق شجرةَ HEAD المحلّيّ** [PA-09]

    **وهذا هو دليلُ `M15` الناجية**: `PA-09` لا يُقاس في اختبارٍ لا ينادي شبكةً، فقياسُه
    الوحيدُ المتاحُ **أن يُدفع به دفعٌ حقيقيٌّ فيُقابل الشجرتَين ويُذن**. وقد وقع. والبصمةُ
    تختلف عن المحلّيّةِ حتمًا (الـAPI يُعيد كتابةَ المُلزِم) — **فالهويّةُ شجرةٌ لا هاش**،
    وهو عينُ ما قتلت طفرةُ `M2` نقيضَه.

      التشغيلة  : 96 · المُعرَّف 33220457148 · الرأس 21557f45
      الحال     : completed · النتيجة **success**
      الوظيفة   : «بناء + اختبار + سلامة السجل + مدقّق التوثيق»
      الخطوات   : **22 من 22 ناجحةً** · لا خطوةَ فاشلةً ولا مشطوبةً واحدة

    **وقُرئ كلُّ استنتاجِ خطوةٍ لا استنتاجُ التشغيلةِ وحدَه** (درسُ `T-142`): فتشغيلةٌ
    تُعلن `success` وفيها خطوةٌ مشطوبةٌ **بوابةٌ لم تُشغَّل** (RULE-001).

    **وسقوطُ «قبول 37» المُعلَنُ في §9 لم يقع على الدمج**: المشيةُ هناك أخفُّ حِملًا،
    **وهذا نفسُه دليلُ أنّ العلّةَ عتبةٌ زمنيّةٌ مطلقةٌ لا خللٌ منطقيّ** — ودَينُها
    `W-2026-004` (`BLOCKED`) لا هذا البند. فحكمُ السلسلةِ المحلّيّةِ يبقى كما كُتب: أخضرُ
