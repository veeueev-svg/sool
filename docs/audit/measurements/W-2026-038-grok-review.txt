Original gap, quoted from 01-verdict-2026-08-22.md §3 and criteria/C-09.md: network prevention is application-level inside the process; there is no confinement at container and kernel level. The in-process egress guard had already PASSed the independent probe (undeclared host refused, channel contained after three tries). That PASS was not enough, and it is still not enough.

What the raw files actually show:

phase-39-T16.txt, on the development process, reports confined=false with five unsatisfied conditions (empty_bounding_set, no_new_privileges, seccomp_filter, read_only_root, default_deny_egress). Section 3: a raw net.connect outside a confined namespace returns OUTCOME=connected. Section 4: the same attempt inside `unshare --net` returns OUTCOME=error CODE=ENETUNREACH. Section 5 inside that namespace: interfaces=lo, defaultRoutes=0. Section 6: docker, podman, iptables, nft are all absent in that environment; unshare/ip/capsh are present. That file is a real measurement of two facts: (a) in-process code does not stop a raw connect, which is exactly the original gap, and (b) a kernel net namespace with no default route does stop it. (b) is a primitive, not a demonstration that the state workload runs that way.

phase-39-T16-container.txt reports, as `/proc` facts: uid=10001, CapEff=0, CapBnd=0, NoNewPrivs=true, Seccomp=2, readOnlyRoot=true, interfaces=lo, defaultRoutes=0, confined=true, unsatisfied=0. It does not contain a connect attempt. It does not name the state binary. It wraps the facts in the witness’s own closing sentence that T-16 is “سدّت قياساً”. A witness declaring the gap closed is not an auditor’s verdict.

src_security_confinement.ts is a reader, not an enforcer. It reads `/proc` (Uid, CapEff, CapBnd, NoNewPrivs, Seccomp, net/dev, net/route, self/mountinfo) and scores seven named requirements. Comments in the file itself state the unit “does not create confinement, does not install it, and does not lower it”; the operator of the container does that. The witness root is a parameter, swapped for a fake tree in tests. Inability to read `/proc` is a closed failure, which is sound as far as it goes.

The default_deny_egress test is not an egress test. evaluate() sets
`ok: facts.defaultRoutes === 0`.
countDefaultRoutes() reads only `/proc/net/route` (IPv4), skips `lo`, and counts destination 00000000. It does not require interfaces ⊆ {lo}. It does not read `/proc/net/ipv6_route`. It does not fail on a non-default route to a reachable network. ADR-0026 states this as policy (“measurement is of the path not the name”). That policy leaves a hole the original C-09 text does not permit: “zero undeclared external network effect” is not implied by “zero IPv4 default routes.”

src_security_egress_manifest.ts generates three texts: a Kubernetes NetworkPolicy with egress: [], a CiliumNetworkPolicy with toFQDNs plus a DNS rule `matchPattern: "*"` toward kube-dns, and a compose file with internal: true. Those are strings. The package contains no byte-for-byte check output, no Dockerfile, no compose.yaml, no workflow YAML, and no CI log — only a formatted extract. The Cilium allowlist’s DNS `*` is a declared covert-channel surface; the compose file, by ADR-0026 deviation 2, blocks all egress including declared counterparties. Neither generated artifact is shown applied to a running state process.

phase-39-T16.md (claim) describes the CI invocation:
`docker run --rm --network=none --cap-drop=ALL --security-opt no-new-privileges --read-only --tmpfs /tmp:... --entrypoint /nodejs/bin/node ... dist/scripts/confinement_witness.js`
The confinement attributes in the container extract are therefore the product of extra docker-run flags plus an entrypoint override. The job ran the witness, not the state. If production starts the image without those flags, this measurement says nothing. The package does not include the image’s default ENTRYPOINT/CMD, so it cannot show the image is self-confining.

ADR-0026, under “what this item did not close,” still declares: the state was not run in an actual container inside this repository. That admission is dated against phase-39-T16.txt (2026-08-23). The later container extract (2026-09-07) does not retract it in source; it substitutes a witness process. ADR-0026 also lists deviations that shrink the claim: FQDN allowlisting needs Cilium; compose internal:true is total-block not declared-only; seccomp is the operator default, not a committed profile; check:confinement does not fail an unconfined development process; unshare is not production.

02-COMPLETION_CRITERIA.md still lists T-124 as an unmet external condition requiring a real managed-operator container environment with a re-runnable boot report and an audit-chain id. The package has no such report.

Why the gap is upheld: T-16 asked for container-and-kernel confinement of the state, not a `/proc` self-report of a witness started with injected flags, and not an unshare demonstration on a probe process. C-09’s text is “zero undeclared external network effect.” The only raw connect measurements in the package are connected (unconfined) and ENETUNREACH (unshare --net). There is no connect measurement from inside the container, and none from the state process. `/proc` describes the witness to itself. That is not egress prevention of the workload. Blocking defect: STATE_PROCESS_NOT_SHOWN_CONFINED.

## C-13 — T-21 — UPGRADE_TO_SATISFIED

Files read by name:

Original status: the auditor did not re-measure, because there was no inference engine, so the measurable property was quarantine-at-registration, not refusal-at-run. T-21 is that hole. The criterion text is a prohibition: an unsigned or unevaluated model shall not be run.

src_models_inference.ts implements InferenceEngine.run(). Refusal is the default. Conditions re-checked on every call, not once at bind: kill switch, active version, registry record, bound runtime, digest match, attestation present, attestation suite digest, attestation expiry, concurrency cap, then output-length and latency after infer(). Each allow and each refuse is appended to the audit log. bindRuntime matching digests is explicitly not a run permit. src_kernel_config_inference.ts refuses to load if require_active, require_digest_match, or require_attestation is not true, if default is not deny, if max_safety_failures or max_denial_breach is not 0, if production_severity is not critical. That is a gate whose knobs cannot be turned off from config.

phase-39-T21.txt, header honesty clause: the responder used here is a baseline reference, not a trained model; what is measured is the run gate and attestation, not model quality. The raw checks: unregistered/quarantined → INFERENCE_NOT_ACTIVE at the run point (quarantined remains so after weights are bound); digest mismatch → INFERENCE_DIGEST_MISMATCH; active without runtime → INFERENCE_NO_RUNTIME; no attestation → INFERENCE_NO_ATTESTATION (the C-13 sentence); stale attestation → INFERENCE_ATTESTATION_STALE; revoke between calls blocks the second; kill switch overrides; the fully qualified case runs (output length 92). Safety suite: 23 safety / 8 benign / 8 categories / distinctness=1; the old canned line that used to score 3/3 now fails SAFETY_OUTPUT_NOT_DISTINCT; a silent wall that rejects everything fails the same. Load: 256 calls, 128 allowed, 128 refused, breach=0, p99=0.054ms, 256 audit entries for 256 calls.

Does a gate in front of a non-model satisfy “an unsigned model shall not be run”? Yes, as a prohibition. The criterion does not require that a trained neural network exist. It requires that unsigned or unevaluated models not be executed. A run entrypoint that refuses those cases, with attestation required and not disableable from config, is the property T-21 said could not be measured. Vacuous reading: if no trained model is bound, no unsigned trained model runs. Non-vacuous reading: the stub itself is an artifact that is refused until attested, and refused again if attestation is stale or the suite digest moves. Either reading closes the named gap.

What this does not prove, and what I do not upgrade on: that InferenceEngine.run() is the only call site in a repository I have not been given; that the safety suite transfers to a future trained model; that infer() being synchronous `(p: string) => string` can actually be interrupted by maxLatencyMs (the timeout is checked after infer() returns). Those are residual. The implementer’s own open item — binding a real trained model — is residual, not T-21.

Upgrade: T-21 asked for a run path at which unsigned/unevaluated is refused. The source is that path. The raw probe measures the refusals at that path. No blocking defect.
